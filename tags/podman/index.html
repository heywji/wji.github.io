板子一直显示 no link：根因是 DHCP 下发的网关

桌上有一块 ESP32-P4 的小板，用来显示各个 AI 的额度。它平时直连 Mac 上的采集程序（bridge）；直连不通时，退回去走一个 relay（经过 Cloudflare Tunnel）。 这周我把 relay 从 192.168.1.244 搬到了 Mac 上，搬完板子右上角就一直是 × no link。我一开始以为是搬迁搞坏的。 这篇记它怎么被证伪，以及最后落到的根因：板子从 DHCP 拿到的网关是 192.168.1.1，经它访问 Cloudflare 有相当比例的连接超时；而我的 Mac 走的是旁路网关 192.168.1.254，一直正常。 文中域名、token、Wi-Fi 信息均已抹去；内网地址是真实的。 ...

这周的主线是两件事：wenkangnas.local (192.168.1.4) 上一台虚拟机的 CPU 被吃满，一路查到 OpenClaw 网关的内存问题；以及把桌上 ESP32 小板依赖的中继服务从虚拟机搬到了 Mac 上，顺手把板子一直显示的 no link 查清楚。 NAS CPU 压力大：其实是 OpenClaw 网关在漏内存 NAS（4 核）load 到了 5.5–6.3，全是 CPU 压力，IO 压力很低。top 里是两个 qemu 进程，对上 VMM 里的两台虚拟机；大头是 192.168.1.244（2 vCPU / 4 GB，已经跑了 35 天）。登进去看，是 OpenClaw gateway 的 node 进程堆内存涨到了 --max-old-space-size=2048 的上限，Node 一直在 GC，VM 同时在大量 swap（swap 一度用到 3.9 GB），这些 swap IO 落到 NAS 上，NAS 的内核态 CPU 也跟着高。journal 里能看到它之前以 ABRT 崩过两次（10/11 和 10/14），大约三天一次，很符合堆耗尽。 ...
