# 手册 01：前台文本发送助手的目标、边界与最小实现

## 目标

实现一个和我当前工作流一致的本地前台文本发送工具，用来把本地文本可靠发送到：

- `remote-viewer`
- SPICE
- VNC
- 其他可以手动聚焦的普通桌面窗口

这个工具的定位是：

- 本机使用
- 前台使用
- 显式点击触发
- 辅助输入

不是：

- 后台驻留程序
- 静默自动发送工具
- 远程控制框架
- 剪贴板监听或篡改工具

## 最小功能集合

第一版必须有这些能力：

1. GUI 模式
2. CLI 模式
3. 从文本框读取内容
4. 从 stdin 读取内容
5. 从本地剪贴板加载内容
6. 发送前延迟
7. 字符间隔设置
8. 安全标签白名单

推荐第一版只支持这些标签：

- `<ENTER>`
- `<TAB>`
- `<ESC>`
- `<CTRL+C>`
- `<CTRL+V>`

## 明确边界

这些能力默认不要做：

- 开机自启
- 后台驻留
- 全局键盘钩子
- 隐身运行
- 静默批量发送
- 剪贴板监听
- 剪贴板替换
- 面向密码框或系统安全对话框的特殊处理

如果 AI 没有先把这些边界写清楚，就不要让它直接开始编码。

## 推荐目录结构

如果做成多文件，推荐像这样：

```text
project/
  app.py
  core/
    parser.py
    sender.py
  backend/
    base.py
    xdotool_backend.py
    ydotool_backend.py
  ui/
    tkinter_app.py
  README.md
```

如果做成单文件，也至少要把这几个层次分开：

1. 输入来源
2. 标签解析
3. 发送调度
4. 输入后端
5. GUI / CLI 入口

## 最小实现步骤

### 步骤 1：统一输入来源

先把三种输入方式统一成同一种内部字符串：

- `--text`
- `--stdin`
- GUI 文本框

剪贴板加载只作为 GUI 的便捷入口，不要让剪贴板本身变成后台依赖。

### 步骤 2：实现安全标签解析

做一个独立解析层，把文本拆成：

- 普通文本片段
- 标签片段

不要把执行逻辑混到解析函数里。解析层只负责产出结构化 token。

### 步骤 3：做统一发送管线

核心发送函数应该只接收：

- token 列表
- delay
- interval
- backend

GUI 和 CLI 必须共用同一套发送逻辑，不要各写一份。

### 步骤 4：实现前台交互流程

发送流程固定为：

1. 用户点击发送或执行 CLI
2. 工具明确提示倒计时开始
3. 用户自己切换到目标窗口
4. 倒计时结束后开始发送
5. 发送完成后给出明确结果

### 步骤 5：先做一个最小可交付版本

第一版只要求：

- 普通文本发送稳定
- `<ENTER>` 稳定
- GUI 能加载剪贴板
- CLI 能从 stdin 读取
- 错误信息可读

不要一开始就追求支持一大堆组合键。

## 验收标准

至少完成这些测试：

1. GUI 文本框输入一段文本并发送成功
2. GUI 从剪贴板加载文本并发送成功
3. CLI `--text` 发送成功
4. CLI `--stdin` 发送成功
5. 文本中包含 `<ENTER>` 时行为正确
6. 倒计时期间能手动切到目标窗口
7. 缺少依赖时能看到明确报错

## 常见失败点

最常见的错误不是 GUI，而是这几个地方：

- GUI 和 CLI 走了两套执行路径
- 文本解析和输入执行耦合在一起
- 把所有 Linux 会话都当成 X11
- 第一版就塞了过多标签，导致可测试性变差

如果手册 01 已经落地，下一步就不要继续堆功能，而是进入手册 02，把输入后端和 Wayland 支持补齐。
